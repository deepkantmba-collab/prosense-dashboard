Privacy Guard — Keeping the Models to Metadata Only (🧪 Designed, not built)

The goal: read the words, keep only the numbers. This is not one new AI model. It is a safety layer made of standard parts that sits in front of the scoring models, so the rule is enforced by design and not by good intentions. Status: designed, not built or trained.

1
Hold in memory
A comment or message is read into memory only. It is never saved first.
2
Detect and mask
Rules plus a small name finder, run inside our own system, mask names, emails, IDs and phone numbers.
3
Score
The current phrase engine (420 phrases, fully explainable) turns the text into pillar scores. A small local language model such as the BERT Fear Index can replace it later. No outside AI service ever sees the text.
4
Discard
The text is dropped from memory. It is not written to disk, logs, the training table or the chat.
5
Allow-list
Only numbers can pass: pillar scores, a band, a phrase count. Any text field or long string is rejected, not stored. Embeddings are not stored either, because they can be reversed back into words.
6
Group before showing
Team views need at least 5 people. Smaller groups show no breakdown. Optional small noise on totals.
7
Audit and review
A log records when a score was made and by which model version, but never the content. A human checks any alert before action.
✅ What is kept
Pillar scores, a band (low / medium / high), counts, model version, timestamp.
⛔ What is never kept
The wording, names, embeddings, full messages, or anything sent to an outside AI service.

Where it can still go wrong. A score about a person is still personal data, and burnout is health-related, so consent and GDPR still apply. A very small team can reveal one person, which is why the group minimum exists. A masking tool can miss a rare name, which is why the text is also discarded after scoring and a human reviews alerts. Today the phrase engine is rule-based and explainable, which makes it easier to control than a black box.

Known Challenges & Honest Limitations
An academic panel expects you to own your limitations. Hiding them looks worse than naming them.
RESOLVED — VADER Failure
VADER misclassified workplace language ("I go with the model" → positive). Built custom NLP engine instead. 420 phrases, seed=42, 0 mismatches.
RESOLVED — Class Imbalance
67.1% at-risk vs 32.9% healthy — ratio 2.04:1. Fixed with class_weight="balanced" in both trained models (no SMOTE needed).
RESOLVED — Multicollinearity
psysafe_score ↔ outcome_score r=0.914. VIF analysis run: 34 of 41 features dropped (VIF > 10); 7 clean features used for training.
CRITICAL — Fully Synthetic Data
No real org signals used. Models trained on synthetic patterns may not generalise to real teams. Biggest production risk before any enterprise deployment.
WEAK NLP — WLB, Job Sat, AI Adoption
r=0.305 (WLB), 0.460 (Job Sat), 0.469 (AI Adoption). Language signals too indirect for these pillars. Phrase redesign planned.
DESIGNED — BERT Fear Index Not Yet Trained
Designed and simulated only (planned v0.9.2, 25% canary rollout). Training, SHAP explainability and bias audit are next steps.
BLOCKING — Privacy & GDPR Framework Not Formalised
Cannot deploy to real users until consent framework, data residency, and audit logging are defined. Privacy by Design is a design principle here — not yet an implemented system.
Current status: PoC — demonstrable to design partners and academic panels. Not MVP. Step 12 is complete. Next step to MVP: connect one real (consented) data source + define consent framework + run a real pilot.
